# העלאת שיעורים לערוץ החדש ביוטיוב (גנזי חיים)

שני חלקים נפרדים:
- **א. בענן (GitHub Actions), בלי מחשב של הרב:** מעתיק כותרת, תיאור וסדרה לסרטונים שהרב **כבר העלה ידנית** לערוץ החדש. ראו "הרצה בענן" למטה.
- **ב. על המחשב של הרב:** מעלה בעצמו את הקבצים מהתיקייה (ומעתיק את הפרטים). אופציונלי.

סקריפט אחד שרץ על המחשב של הרב (או של מי שיש אצלו הקבצים). בלי התקנות חוץ מ-Node.js, בלי תלויות.

**מה הוא עושה**
1. **מעלה** קובצי וידאו מתיקייה לערוץ `@ginzei-haim` (העלאה שממשיכה מאותה נקודה אם נפסקה), ולכל קובץ מוצא את השיעור המתאים בערוץ הישן (לפי שם הקובץ) ו**מעתיק משם כותרת, תיאור, תגיות וסדרה** (פלייליסט). אם הפלייליסט לא קיים בערוץ החדש, הוא נוצר באותו שם.
2. **מתקן** סרטונים שהרב כבר העלה ידנית ב-YouTube Studio: מזהה לאיזה שיעור ישן הם שייכים (לפי שם, ולפי **משך הסרטון**, אותו קובץ הוא אותו משך) ומעתיק את אותם שלושה פרטים. מצב `--fix-only`.
3. **מכבד את המכסה היומית** של יוטיוב: עוצר בנקיות כשנגמרה, זוכר מה כבר נעשה (`state.json`), וממשיך בריצה הבאה. עם `--keep-going` הוא ממתין ללילה וממשיך לבד.
4. כותב `report.csv` אחרי כל ריצה: מה הועלה, מה תוקן, ומה לא נמצא לו שיעור מתאים.

## הגדרה חד-פעמית (Tal)
1. **Google Cloud**: https://console.cloud.google.com → פרויקט חדש (למשל `ginzei-haim-youtube`).
2. APIs & Services → Library → **YouTube Data API v3** → Enable.
3. **OAuth consent screen** (או Google Auth Platform): שם אפליקציה, אימייל תמיכה; סוג **External**; בהוספת Test users לרשום את האימייל של הרב.
   **חשוב:** אחרי שהכול עובד, לעבור ל-**Publish app / In production**. כל עוד האפליקציה במצב Testing, ההרשאה של הרב פגה כל 7 ימים. במצב Production יופיע מסך "Google hasn't verified this app", ממשיכים עם Advanced → Go to ... (זה בסדר, האפליקציה פרטית).
4. Credentials → Create credentials → **OAuth client ID** → סוג **Desktop app** → Download JSON. לשנות את שם הקובץ ל-`client_secret.json` ולשים בתיקייה הזאת.
   (הקובץ לא נשמר ב-git. להעביר לרב בדרך פרטית, לא בצ'אט ציבורי.)
5. **מכסה וביקורת:** ברירת המחדל היא 10,000 יחידות ליום, העלאה עולה 1,600, כלומר כ-**6 העלאות ביום**. ועוד: סרטונים שמועלים דרך API מפרויקט שלא עבר ביקורת ננעלים כ**פרטיים**. הפתרון: למלא את הטופס שבקובץ [`QUOTA-REQUEST.md`](QUOTA-REQUEST.md) (אפשר לעשות את זה במקביל להעלאות).
   העלאה ידנית ב-Studio לא סובלת מהנעילה, ומצב `--fix-only` צורך רק ~100 סרטונים ליום ולא דורש הגדלה.
6. כדאי שהערוץ יהיה **מאומת בטלפון** (https://www.youtube.com/verify), אחרת יוטיוב מגבילה העלאות ביום.

## הרצה בענן (העתקת פרטים, חלק א)
Workflow: `.github/workflows/youtube-fix.yml` ("העתקת פרטי שיעורים לערוץ החדש ביוטיוב"). רץ פעם ביום ובהפעלה ידנית.
בכל ריצה: רשימת הסרטונים בערוץ החדש ← התאמה לשיעור הישן (שם או משך) ← עדכון כותרת/תיאור/תגיות ← הוספה לפלייליסט הנכון. המצב נשמר ב-`data/youtube-fix-state.json` והדוח ב-`data/youtube-fix-report.csv`, ואפשר לראות אותו גם בסיכום הריצה ב-Actions.
**הרצה ראשונה תמיד בבדיקה בלבד** (Run workflow עם dry_run מסומן, ברירת המחדל), לקרוא את הדוח, ורק אז להריץ בלי.

הגדרה חד-פעמית, בלי שהרב יצטרך להתקין משהו:
1. **הרב מוסיף את Tal כמנהל של הערוץ:** YouTube Studio ← Settings ← Permissions ← Invite ← האימייל של Tal ← תפקיד **Manager** (או Owner). כך Tal מתחבר בעצמו, בלי סיסמאות של הרב.
2. אחרי שלבים 1-4 של "הגדרה חד-פעמית" למעלה (Google Cloud, כולל **Publish app**), Tal מריץ אצלו במחשב: `node ginzei-youtube.mjs --login` (בתיקייה הזאת, עם `client_secret.json`). בדפדפן לבחור את חשבון Tal ואת הערוץ **גנזי חיים**.
3. בריפו: Settings ← Secrets and variables ← Actions ← New repository secret, שלושה סודות: `YT_CLIENT_ID`, `YT_CLIENT_SECRET` (מתוך `client_secret.json`) ו-`YT_REFRESH_TOKEN` (הערך `refresh_token` מתוך `token.json`). את הערכים לא שולחים בצ'אט.
4. Actions ← "העתקת פרטי שיעורים לערוץ החדש ביוטיוב" ← Run workflow (בדיקה בלבד) ← לקרוא את הדוח ← להריץ שוב בלי dry_run.
5. כשכל השיעורים הועברו, למחוק את שורת ה-`schedule` מה-workflow.

חשוב: אם ההרשאה פגה (מצב Testing של האפליקציה בגוגל, או ביטול), הריצה נכשלת עם הודעה ברורה וצריך שלב 2-3 שוב.

## הוראות לרב (הרצה על המחשב, חלק ב)
1. להתקין Node.js (הגרסה LTS) מ-https://nodejs.org
2. להעתיק את התיקייה הזאת למחשב. לשים בה את `client_secret.json` שקיבל.
3. **בדיקה בלי לשנות כלום:** בחלון טרמינל בתיקייה: `node ginzei-youtube.mjs --dry-run --folder "הנתיב לתיקיית הוידאו"`. נוצר `report.csv`, לפתוח באקסל ולראות שההתאמות נכונות.
4. **הרצה:** לחיצה כפולה על `run.command` (מק) או `run.bat` (ווינדוס). בפעם הראשונה:
   - ייפתח דפדפן. להתחבר עם חשבון הגוגל של הערוץ, לבחור את הערוץ **גנזי חיים**, ללחוץ Advanced → Go to ... → לאשר.
   - הסקריפט ישאל את נתיב תיקיית הוידאו (אפשר לגרור את התיקייה לחלון).
5. להשאיר את החלון פתוח. אחרי שנגמרת המכסה היומית הוא ממתין וממשיך מחר. אפשר גם לסגור ולהריץ שוב מחר, הוא ממשיך מאותו מקום.
6. רק לתקן סרטונים שכבר הועלו ב-Studio: `fix-only.command` / `fix-only.bat`. (אפשר להריץ כמה פעמים, מה שכבר תוקן לא נוגעים בו.)

## איך מתאימים קובץ או סרטון לשיעור
הרשימה של השיעורים בערוץ הישן ב-`lessons-list.json` (נוצר מנתוני האתר ע"י `node build-list.mjs`; מריצים שוב כשיש שיעורים חדשים בערוץ הישן).
- **קובץ מקומי:** (1) שם הקובץ זהה לשם קובץ ה-mp3 של השיעור (`JH-26-11-11 Tfila - ... - BVG`); (2) תאריך בשם הקובץ בצורת שנה-חודש-יום (`26-11-12`), עם קוד המקום אם יש, ומילים משותפות עם שם קובץ השמע. כך גם שמות כמו `Shiur 87 Hanuka 26-11-12 Yod Gemel Mecilan.mp4`. אם באותו תאריך כמה שיעורים והשם לא מכריע, זה מופיע בדוח; (3) שם הקובץ זהה לכותרת השיעור. כדי שלא יותאם בטעות שיעור של רב אחר באותו תאריך, התאמה לפי תאריך בלבד מועלית רק אם שם הקובץ מתחיל ב-`Shiur` או `JH` (אפשר לשנות ב-`settings.json` בשדה `namePrefixes`). עדיף שהתיקייה תכיל רק שיעורים של הרב. שם שלא חד-משמעי לא מועלה אלא נרשם ב-`report.csv`.
  תיקון ידני: קובץ `file-map.csv` עם שורות `שם-קובץ.mp4,מזהה-יוטיוב-של-השיעור-הישן`.
- **סרטון שכבר בערוץ החדש:** לפי השם (בדרך כלל שם הקובץ), ואם אין, לפי משך זהה (עד שנייה) כשהוא ייחודי. התאמה לפי משך בלבד מסומנת בדוח; `--careful` מדלג עליהן.

## איך האתר לא מציג את השיעור פעמיים
האתר מושך משני הערוצים. ב-`scripts/sync.mjs`: שיעור עם **אותה כותרת** (ומשך שזהה עד 10 שניות) בשני הערוצים מוצג פעם אחת, מהערוץ החדש. והשיעור יורש את **תאריך השיעור המקורי**, מספר הצפיות הגבוה, וקובצי ה-mp3/PDF של הסרטון הישן.
לכן חשוב שהכותרת בערוץ החדש תהיה זהה לישנה, וזה בדיוק מה שהסקריפט עושה. אפשר למחוק את הסרטונים הישנים בערוץ הישן אחר כך, והאתר יישאר תקין.
